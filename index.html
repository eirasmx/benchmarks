🥇 Fix 3 — Parallelize ir.json with WASM compile
−12ms wasm-bridge.js easy
_loadIR() was awaited sequentially after WASM instantiation. ir.json is an independent network request — kick off fetch(irUrl) alongside the WASM glue import, then register bindings via Promise.all. The ir.json payload (~8–25KB) typically arrives before WASM compile finishes, making registration cost ~0 wall-time.
Before — serial
await wasmMod.default(...) // ir.json waits for compile await _loadIR(runtime, irUrl)
After — parallel
const irFetch = fetch(irUrl) await wasmMod.default(...) // irFetch already in flight await _loadIR(runtime, irFetch)
🥈 Fix 4 — <link rel="modulepreload"> via packager
−15–25ms clera_packager.py medium
No preload hints were injected for CRE assets. The browser didn't know about cre.wasm, cre_runtime.js, or ir.json until WASMBridge.init() ran — ~30–50ms of dead network time. The packager now injects three preload hints into <head> at build time, so the browser pre-fetches in parallel with HTML parsing.
Packager injects into <head>
<link rel="preload" href="__cre__/wasm/cre.wasm" as="fetch" crossorigin> <link rel="modulepreload" href="__cre__/wasm/cre_runtime.js"> <link rel="preload" href="__cre__/wasm/ir.json" as="fetch" crossorigin>
Effect on boot timeline
HTML parse begins ↓ browser sees preloads ↓ all 3 fetches start JS evaluates (clera.js) ↓ WASMBridge.init() ↓ assets already cached
🥈 Fix 5 — Inline ir.json into HTML at build time
−12ms RTT clera_packager.py + wasm-bridge.js medium
ir.json is build-time static. The packager inlines it directly into index.html as <script id="cre-ir" type="application/json">. _loadIR() checks for this element before fetching — if present, parse from DOM (sync, zero network). Eliminates the ir.json RTT entirely. When combined with Fix 3, the ir.json fetch becomes a no-op.
packager: _build_html()
ir_json = json.dumps(ir) html = html.replace( '</body>', f'<script id="cre-ir" type="application/json"> {ir_json}</script>\n</body>' )
wasm-bridge.js: _loadIR()
const el = document.getElementById('cre-ir') if (el) { ir = JSON.parse(el.textContent) } else { const r = await fetch(irUrl) ir = await r.json() }
🥉 Fix 7 — Streaming WASM compilation
−10–20ms (first visit) wasm-bridge.js medium
WebAssembly.compileStreaming(fetch(url)) starts the compiler as bytes arrive, rather than waiting for the full download. V8's Liftoff tier-1 compiler typically keeps up with a 4G stream, so compilation finishes as the last byte lands. Only relevant for the first-visit path — IDB cache skips it on repeats. Requires Content-Type: application/wasm from the dev server.
⚙️ Fix 8 — cre_runtime.js script tag (eliminate dynamic import round-trip)
−5ms clera_packager.py + wasm-bridge.js low-risk
cre_runtime.js was loaded via await import(glueUrl) where glueUrl was derived by string-replacing cre.wasm with cre_runtime.js. The packager now injects a <script type="module" src="__cre__/wasm/cre_runtime.js"> tag directly into HTML alongside the Fix 4 preloads, eliminating the dynamic import scheduling delay and the URL hack.
